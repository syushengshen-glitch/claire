Code Review: summarizeOrders
1. Bugs and Vulnerabilities

Off-By-One Index Bug (TypeError: Cannot read properties of undefined)

Cause: The loop condition i <= orders.length attempts to access orders[orders.length], which evaluates to undefined.

Consequence: Accessing orders[i].amount on the last iteration throws a runtime TypeError.

Division by Zero (NaN Average)

Cause: Passing an empty array [] sets orders.length to 0, resulting in 0 / 0.

Consequence: average evaluates to NaN.

Spread Operator on Empty Array (-Infinity Highest)

Cause: Math.max(...[]) evaluates to Math.max(), which equals -Infinity.

Consequence: highest evaluates to -Infinity when orders is empty.

Unhandled Missing/Invalid amount Properties (NaN Contamination)

Cause: If an order object is missing the amount property or contains undefined/null/NaN, total += orders[i].amount turns total into NaN, corrupting average and highest.

Non-Array or Null/Undefined Input Failure

Cause: If orders is null, undefined, or not an array, accessing orders.length or calling .map() throws a TypeError.

2. Corrected Code
JavaScript
function summarizeOrders(orders) {
  // Guard against non-array or empty input
  if (!Array.isArray(orders) || orders.length === 0) {
    return {
      total: 0,
      average: 0,
      highest: 0
    };
  }

  let total = 0;
  let highest = -Infinity;
  let validCount = 0;

  for (let i = 0; i < orders.length; i++) {
    const order = orders[i];
    
    // Safely extract and validate amount
    if (order && typeof order.amount === 'number' && !isNaN(order.amount)) {
      const amount = order.amount;
      total += amount;
      if (amount > highest) {
        highest = amount;
      }
      validCount++;
    }
  }

  // Handle case where array had items, but no valid numeric amounts
  if (validCount === 0) {
    return {
      total: 0,
      average: 0,
      highest: 0
    };
  }

  return {
    total,
    average: total / validCount,
    highest
  };
}

5. Assumptions and Limitations

Floating-Point Precision: Uses native JavaScript IEEE 754 floating-point numbers. Sums/averages with decimal currency values may exhibit precision artifacts (e.g., 0.1 + 0.2 = 0.30000000000000004). In a production setting involving real currency, amounts should be handled in cents/integers or formatted with Number.prototype.toFixed() / Intl.NumberFormat.

Strict Type Checking: String representation of numbers (e.g., amount: "100") are ignored rather than coerced to avoid unpredictable type conversions ("100" + 50 = "10050").

Invalid Item Exclusion: Orders without a valid numeric amount are excluded from both the total sum and the average count. If an array contains 3 objects but only 2 have valid amounts, average is divided by 2.

Default Safe Values: Returns { total: 0, average: 0, highest: 0 } for invalid or empty inputs to ensure callers always receive a predictable object shape.
